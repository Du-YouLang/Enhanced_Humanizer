# 产品 PR 审核与交付

只有项目私有授权文件指定的 GitHub 账号、仓库、可见性和 `codex/` 分支空间可用。工作台“PR 审核提案”先核验当前账号/权限/可见性、远程 main 精确提交、候选祖先关系、独立通过的测试、已保存 artifact 完整性，以及全部待上传提交历史中的私有路径和密钥。无法关联目标 main 的历史合成任务会被拒绝，不会把它们上传到本项目。

提案绑定候选 head、目标仓库/base、远程 base SHA、完整 diff SHA、测试证据和隐私扫描 SHA。所有者查看代码及证据后，在本机浏览器为该提案填写理由并人工批准；随后才能点击“按此次人工批准创建 Draft PR”。每次批准只使用一次，任何 head、目标、base、测试或扫描变化都要求重新提案审核。未配置授权的安装预览保持本地审核。

交付只推送一个新 `codex/product-pr-<nonce>` 分支并创建 Draft PR，不合并、不发布产品、不改可见性或权限。GitHub CI 与 GitHub 上的人工审核完成后，由人处理合并。发生网络错误或无法确定创建结果时，保存分支/状态并消费该批准，禁止自动重放；先核对远程结果，再决定是否需要新的提案。

`tests/test_publish.py` 使用真实本地 Git 和明确标注的远程/人工审批 fixture，验证错账号、错目标、可见性变化、base 变化、测试失效、历史中曾出现后删除的私有文件，以及结果不明后的重复发布拒绝。Fixture 不是实际用户批准，真实产品 PR 的端到端验收需用户在准备好的提案上操作。
