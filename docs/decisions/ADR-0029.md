# ADR-0029: Continue frozen numerical acceptance after human shutdown

Date: 2026-10-13. Status: authorized by the user's instruction to continue.

The user stopped the local benchmark before shutdown and now requests continuation.
Eleven v12-final2 tasks and their trace sensitivity runs are complete. PC-ALM's
model sessions, public pools and six selections finished before shutdown, but its
independent numerical acceptance did not. Black-5 remains infrastructure pending.

The original runtime, contract, manifest, candidates, budgets and old batch indexes
remain immutable. A supplemental native entry verifies complete candidate evidence,
the exact public pools, selection hashes, original source hashes and environment.
It resumes acceptance only and cannot launch a model or read a credential. It
reuses completed acceptance verdicts, including FAIL and INDETERMINATE, and grades
only missing programs with the original scientific sandbox and oracle. Interrupted
training has no general checkpoint; an unfinished evaluation restarts separately
while all partial output remains preserved. No completed model task is replayed.

Five acceptance files were complete before shutdown. The stopping controller
subsequently wrote a sixth file for D: `InterruptedError`, with the exact reason
`Owned main controller interrupted by signal 15`. Its timestamp is within the
recorded shutdown interval. This file remains untouched. Its explicit signal
failure is excluded from model failure counting; D's new acceptance is a separate
file bound by the recovery plan and journal. Ordinary scientific FAILs are never
excluded by this rule. The initial preparation that included this late file
performed zero model calls and is retained; the corrected preparation supersedes it.

Each new output has a durable write intent and exclusive creation. A second
shutdown can reuse completed new acceptance outputs. Corrupt/partial journal tails
and unbound outputs block continuation. Process ownership uses native boot ID,
PID start ticks and exact commands; active acceptance blocks new paid work.
Unexpected exits within the current boot require inspection. Only an explicit
human continuation or a new boot permits an unfinished acceptance continuation.

After acceptance completes and its controller exits, the existing supervisor may
run the missing PC-ALM trace sensitivity and previously unstarted scientific tasks
serially under the original cumulative budget. Ambiguous model calls and Black-5
are retained without whole-task replay. The cumulative ledger is not reset or
refunded. The acceptance-only step requires the ledger to remain byte-identical.

Original per-arm monotonic intervals were not checkpointed. They and the original
whole-task wall times are `unavailable`, excluded from timing comparisons. Retained
token/subscription records and completed numerical evaluation timings are reused;
the supplemental recovery duration is reported separately. Numerical success still
requires substantive source/report review where the frozen adapter says so.

The local 30-second monitor and authorized 45-minute heartbeat resume with the new
guard. Windows subprocesses remain windowless. Product PR #30 still awaits human
merge, and external release still requires confirmation. This recovery is neither
full P6 acceptance nor a new P7 package installation acceptance.
