# ADR-0060: Explicit legacy J3 score range and stop on invalid judge output

Date: 2026-11-26. Status: prospective local repair; exact native controls, CI and scoped continuation not yet accepted.

The first two refreshed model-task groups closed Direct and matched-budget programs with public and hidden PASS. Their Enhanced rows remain raw INDETERMINATE: every independent judge returned a ten-point scale, while the reused J3 validator requires integer scores from zero through four. The new refresh wrapper had omitted the explicit range from the original main-protocol judge prompt; the shared rubric object itself does not specify numeric anchors. This is an underspecified experiment interface, not evidence that either tested model cannot solve the task.

Preserve all worker outputs, ranks, original invalid-judgment journals, frozen programs, elapsed time, usage and reservations. Do not rescale those scores, silently mark Enhanced PASS, or replay completed builders, Direct or matched-budget roles. A supplemental adjudication may identify this interface cause while raw outcomes remain unchanged. Any corrected selection requires a separately frozen, metered and scoped continuation; previous hidden outcomes cannot be exposed to judges or builders.

Prospective change: expose the existing integer0..4 contract and exact candidate/ranking/evidence JSON shape in the judge prompt without changing pool bytes, rubric hash, threshold or selection algorithm. Retain validation errors in the journal, then stop at that boundary rather than continuing to invalidate later Enhanced flows. Role timeouts retain their original budget status. Add a zero-provider regression that roundtrips the prompt example through real J3 and rejects ten-point, float, boolean and negative scores; test immutability of the pool and invalid-output stopping.

The active native executor remains immutable. A separate exact-owner controller waits for no open model journals and no STARTED roles before SIGINT; it must not interrupt an active model. Stopping intent is not proof of owner exit. Exact stop, retained-prefix reconciliation, source tests, native controls and CI must be observed before any paid continuation. This repair does not authorize whole-task replay, budget reset, hidden leakage or external publication.
