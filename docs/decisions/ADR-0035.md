# ADR-0035：供应商过载的有限重试和检查点补跑

2026-10-14 用户明确要求：DeepSeek 或 ChatGPT 通道再出现服务器过载时重跑。此授权取代此前对已确认过载格禁止补跑的限制，累计USD200/10000次、角色1000次、请求600秒、输出256000及公共900秒/科研1200秒保持。GitHub和外部发布继续暂缓，产品PR逐次人审不变。

DeepSeek复用既有RecoveryBroker，完整缓冲SSE后才向Harness交付，每个上游wire都预留原账本，最多连续五次临时失败。Pi订阅使用已安装官方SDK的原生自动重试和SessionManager.forkFrom，不新增Coding Harness。供应商内部自动重试仍关闭，SDK dispatch可计数，内部wire不可见。原角色内SDK重连保留已完成工具结果，连续五次失败停止并记录基础设施待重试；认证、费用/额度、请求格式、上下文长度、正常测试失败不据此重跑。

冻结v3原批次继续使用原代码，完成后才从真实终止过载证据选出补跑格。原失败、程序、会话、结果和数值验收不覆盖。每格在独立目录复制自己的文件/Git检查点和官方会话，用官方fork继续未完步骤；禁止重新生成完整16格或读取其他候选。旧角色实耗时间向下扣除剩余预算，请求计数和订阅预留继续累计，旧未知usage不退款。原生会话fork和人工恢复消息应单独报告，不与不中断样本的端到端时延混合。

付费补跑须先通过实际官方SDK、真实本地HTTP、文件/测试/Git的零模型控制：DeepSeek broker过载重连、SDK过载恢复、第五次停止、额度拒绝不重试、原会话fork后不重复已完成工具。失败控制原样保留，新实现独立部署并冻结；准备和合成控制不等于真实模型成功。补跑只针对精确终止过载证据，有工具执行不确定性时先协调现场，不盲目重放。

供应商“overloaded”文案说明当次请求处理能力不足，不证明具体模型被全体用户用满。官方临时过载指导见[OpenAI错误说明](https://developers.openai.com/api/docs/guides/error-codes)，具体SDK与订阅行为以本机固定实现和实际回执为准。
