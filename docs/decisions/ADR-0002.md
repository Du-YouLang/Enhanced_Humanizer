# ADR-0002：复用 Humanize + DSH + Codex，先核查 Windows

状态：proposed（路线按用户明确偏好；运行平台及正式依赖版本待 P0 真实验收）。

关联：WF-01/04、DS-01/02/06、JR-01–09、HR-01/02、BM-04/05/11、OP-05。

采用唯一主编排层 Humanize，使用 `.hmz/flows/` 自定义 Python Flow。DS 候选是完整工程任务，执行交给官方 DSH；Sol 保留直接设计、编辑、测试、重写能力，使用 Codex Harness。Builder、Verifier、Reviewer 的会话与预算独立。

P0 使用 PyPI 发布包核查接口，未检出外部源码、未 Fork。已锁定 `hmz==0.1.0b2`、`deepseek-harness-sdk==0.1.5rc1`、runtime `0.1.5rc1`，并固定完整依赖哈希。`sentry-sdk` 约束在稳定 2.x，关闭 Humanize 遥测。本地 Python 3.13.14、环境、缓存均在项目内。

Windows 实测：CLI/help、Flow API 导入、官方 fake driver、自定义 Flow 加载、下一轮预算拒绝、DSH SDK 初始化与关闭通过；没有发送任何 prompt 到 DSH runtime。不能据此认定真实 Agent 的工具执行、恢复、Token 统计、权限隔离或性能已经可用。

[Humanize 安装文档](https://docs.humanfia.ai/humanize/user/installation)未列 Windows DSH 平台；[PyPI runtime 元数据](https://pypi.org/pypi/deepseek-harness-runtime-bin/0.1.5rc1/json)却提供 win_amd64 wheel。选择实测 Windows 路线，不仅据旧文档安装 WSL。自主执行前还必须解决 ADR-0003 的隔离问题。

替代方案：仅当 Windows 的真实工具协议或隔离门禁失败，提出 WSL2 或受限 Windows 运行环境的具体方案。WSL2 虚拟磁盘必须在本项目内，并需用户批准系统变更。当前未安装 WSL2/Docker，未改现有 Conda 环境。

保留研究边界：P1 对 RLAR（实现/审查/修复）与 Flame Chase（双方直接轮换）实测后选 Flow；P2 用 ADR/实验明确 TurboAgent 请求级采样不替代任务级 N；P6 讨论 Aider/Agentless，不增设首轮必跑臂；OpenEvolve/NVIDIA KDA 作为未来 OP-05 专项，不安装成核心编排依赖。

Jev 仅作实验 Judge；LAV 必须实测 score-token logprobs；Sol 结构化评价不冒充原版概率评分。候选 M 是独立实现并公平重测；收益待冻结基准回答。
