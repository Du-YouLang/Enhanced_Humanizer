# ADR-0004：开发仓库轻量协作与产品 PR 人工审核分开

日期：2026-10-10。状态：依用户本轮明确指示采用；替代 ADR-0003 中开发仓库逐次人工审批/严格 main 保护的原提案，其他数据与执行限制继续有效。

用户要求开发期间给予 Codex 足够自由度，以本地与 GitHub 代码一致为重点，不给开发 PR 施加过多限制；同时明确开发的软件自身的 PR 推送功能必须每一次经过人工审核。

开发仓库采用：阶段分支 + 可追踪提交 + PR + CI。已扫描、CI 通过的 P0 基础设施成果可经 PR 同步 main，无需为每次常规开发提交追加审批；不启用本轮提出的严格服务器 main 保护，不增加 reviewer/协作者要求，不删除历史、不强推。合并部分成果不表示 P0 Gate 已通过，P1 仍须 P0 验收与用户指示。

产品自身采用：每一次 PR 必须有真实人工审核门禁和审核记录；不得把开发仓库的自主权限带给产品执行器，不能以 UI 提示或 Agent 自报批准替代后端执行。产品的审核时点、具体 SHA、拒绝/变更后重新审核将在对应阶段实现和独立验收，保持原需求账本。

本 ADR 作出时 WSL2 安装尚未授权，用户先询问存储需求。随后用户明确批准安装与 C 盘系统组件例外，详见 ADR-0005；该授权独立于开发仓库自由度，不包括自动重启。凭据/研究数据保护与 P0 1 美元/4 请求、Codex 2 回合/120 秒上限继续有效，P1 单独预算已另行确认。

执行记录：P0 Issue #1、PR #2；合并前检查实际 head 的 integrity/secrets，不根据旧提交 CI 判定新提交。远程 main 与本地 main 采用 fetch + fast-forward 对齐；阶段分支和本地 bundle 保留。
