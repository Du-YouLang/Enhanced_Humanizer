# ADR-0020：新的累计预算与原生输出限制分类

2026-10-12 用户明确指定“10k次api调用次数，100$ tokens来完成这些任务”。解释为本轮 P6/P7 累计最多10000次模型API请求、USD100的API Token费用，取先到者；已发生的独立主集用量纳入，不清零，不把订阅用量换算成美元。使用 `configs/budget-p6-main-v2-approved.json`，旧无限总额配置和历史账本快照保留。此用户新上限取代 ADR-0016 的无累计上限表述；本机计算、旧CPU协议、产品PR逐个人审和发布前确认不变。

每次API转发之前，原有跨进程锁内先保留该请求最大费用，并同时检查10000次及USD100保守上界。完整usage才释放多余保留；失败或未知usage不退款。实际账单不可见，保守上界含全部输入按峰值计算，缓存折扣估算不能代替门禁。订阅保持实际保留回合、可见Token和不可见金额分别记录，不购买/充值。

原 `P6_MAIN_LOCAL_20261011` 账本在同一锁内显式修订授权：先保存旧精确字节及SHA，再原子替换授权指纹/总上限，逐请求、订阅和费用字段逐字保留，增加修订历史。实际保留100个已结算API请求、0订阅回合、USD0.6960933 API上界；旧账本SHA为29d3ccae8b601bff3f2d7d5cd318985175e61febd70ed2244f96e880e0dd877a。普通执行仍禁止自动重绑授权，不会重置旧阶段账本。

v5另行冻结16题协议，将DS编码回合请求保护上限从20提升至100，以避免内部低额度过早截断；原115秒角色上限、120秒单请求、1200秒活动上限、4096输出Token上限和私有验收/资源/环境均不变。J1使用原版LAV更窄的独立评分scope上限。不得将v3/v4较窄请求上限下的结果混进v5作为同协议结果。

v4实际再次在首题N3池停止：三候选中两项请求耗尽、一项原生 `turn/end.reason.kind=max-tokens`，后者被Harness包装成INFRA_FAIL。保留该批次和全部用量。v5仅在原生结构化终止记录及其文件SHA可核验、且没有broker策略拒绝时，将此类终止分类为OUTPUT_LIMIT，选中臂FAIL/ROLE_OUTPUT_TOKEN_LIMIT；不靠错误文字猜测，不把半成品记为通过。总预算耗尽、未知provider错误、隔离/策略故障仍停止，无自动重试。新v5是针对已查明问题及新用户预算的明确新实验。
