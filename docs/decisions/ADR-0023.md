# ADR-0023：明确公开文件规则，保留 v8 协议调查样本

2026-10-12，状态：实施；新模型执行以 v9 冻结、零模型控制、干净提交和实际回执为准。

v8 的 Requests-1963 中，DS 原生、一个 DS 池候选、Reviewer 和三项 Sol Builder 共六个角色完成，并通过各自的 112 项公开测试，但均修改了原有 `test_requests.py`，触发不可变文件门禁。提示词只说“保留现有测试、适当添加回归测试”，没有明确禁止在原文件中追加。因此这些结果同时包含协议表达缺陷，不能直接解释为模型不能修复任务。私有验收尚未执行，也不能推断代码已经正确修复隐藏用例。

保留全部 v8 结果、轨迹、协议、源码快照和累计账本。BIP-black-2/Requests-1963 的 A–F 各自收束，两个共同池的完整工具轨迹敏感性也已完成；第三题 BIP-black-1 在调查后由精确 PID/start-ticks 验证的拥有者控制器停止。原续跑索引是 `STOPPED_PRESERVED_NO_AUTOMATIC_RETRY`，未改成成功，不能由手动 continuation 入口重试该已启动任务。

v9 在每个编码角色（包括 Reviewer）的同一任务文本中明确：原有测试、fixture 和依赖配置不可修改，追加也不允许；回归测试只能加入**新文件**。门禁覆盖任何目录深度的 `tests/`、`testing/`、`test_*.py`、`*_test.py` 和 `conftest.py`。失败证据说明被修改的具体路径，不再只给出笼统的“公开测试或提交失败”。公开通过、文件合规、完成/干净提交和私有验收仍分别判定；不降低门槛，也不把 v8 候选改判为通过。

新文件策略以独立真实 Git + OS fence + 公开/隐藏测试验证：原参考实现保留测试可通过；同一实现新增测试文件可通过；仅在原测试文件追加注释仍拒绝；未修改基线也拒绝。它们是零模型控制，不计入主集完成率；控制时账本逐字哈希不得改变。较早在旧部署源码上的控制保留，新源码另存控制回执并绑定源码哈希。

115 秒角色保护、120 秒单请求、1200 秒活动实验、科学私有计算限时、本机硬件、16 个任务/96 单元、seed/repetition、模型和预算累计规则不变。v9 新实验单独冻结，不能混合 v8 成果或挑选最好的旧候选。该修订属于已授权的 benchmark 修复；没有增加预算、购买额度或使用服务器。首次补丁/用户接受等未可靠测得的细分指标继续显式为 unavailable；不能用本次协议修复来声称完整 P6 验收。

产品 PR #30 的真实人审/上传和三项 CI 已通过；GitHub 人工合并仍独立等待。任何包含同一预算提交的开发 PR 不得代替它完成产品合并。P7 已有精确 14c26d2 本地预览交付；v9 的后续源码须明确区分。外部发布仍需用户确认。
