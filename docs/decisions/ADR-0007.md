# ADR-0007：P1 双 Builder Flow、计费代理与独立测试边界

日期：2026-10-10。状态：采用，依据真实实验；保留 v0.4 基线、原版 Flow 和失败证据。

原版 RLAR 实测完成一轮 actor + reviewer：DeepSeek 编辑、测试、commit，Sol 返回 `done/notes` 结构化审查。actor 在循环内复用会话、reviewer 每轮新会话；未完成时等待 5 秒，连续三次 HarnessError 停止。它适合工作与审查循环，不能单独满足两个 Builder 都直接开发的 P1 Gate。

原版 Flame Chase 实测两个新会话轮换：DeepSeek 修复函数，Sol 直接实现流式累加器并提交。只通过仓库交接，状态保存下一位/轮数，每回合等待 5 秒；原版不会因任务已经完成自动结束。本次外部控制器在两回合成功后停止，记录为预期受控停止，不能声称原版自然结束。两个原版 Flow 的代码均未修改；权限由适配层收紧到 local=all、user/system/online=none，故结果是收紧权限后的真实可用性，不代表其默认宽权限表现。

采用薄自定义 `basic_relay` Flow：直接复用 Humanize 的 spawn/run、持久 FlowState、Run.stop/resume 和官方 DSH/Codex 驱动。DS 实现并提交后，程序独立测试、生成事实 handoff，持久保存下一步，实际暂停；resume 只启动新的 Sol 会话。Sol 自主实现另一种设计、补充测试、新建 commit。handoff 包含 base/head、模型角色、测试命令/退出码、改动文件及失败列表；前一模型的聊天文本不作为交接输入。两个内置模式是否进入 UI 留待 P5 决策。这里没有替代 Coding Harness，也没有实现 P2 增强器或评分融合。

计费约束在模型运行前执行。真实 Key 仅由 Windows 读取已有本机 DSH credential ref，经 stdin 送入 Linux 控制器内存，不复制认证目录。控制器 `PR_SET_DUMPABLE=0`；实际测试拒绝模型子进程读取控制器 environ/mem/fd 和合成凭据 canary。DSH 只拿短期本地 capability，网络 fence 只允许计费代理的精确 host:port。Codex 自己的 Linux 登录状态仍是其获授权运行时输入，见 ADR-0006 的边界。

发布的 DSH SDK/runtime 0.1.5rc1 实测使用 `/chat/completions`；固定检出的当前上游源码已使用 Messages。没有把源码 SHA 冒充 wheel 的构建 SHA。另一个实际兼容性问题是 DSH 强制绕过回环 IP 代理。使用发行版 hostname（必须实际解析为 127/8）作为 URL，服务仍只绑定回环地址，经 Humanize 精确 host proxy 到达。模拟端点证明旧回环 IP 路径失败、hostname 路径成功；保留对照，不开放公网监听或放宽网络 fence。

代理只接受固定 deepseek-flash、流式 Chat Completions、usage reporting、封顶 4096 输出 Token 和客户端 function tools。无付费服务端工具、无重定向、无自动充值。按峰值价预留整个 1,048,576 context + 输出上限，即每请求 USD 0.319488；请求前持久写 ledger，再发送 HTTPS。只有完整 `[DONE]`、匹配模型和一致的输入/缓存/输出计数才释放未使用预留；断流/未知 usage/失败保留全部预留。Linux flock 防止多个控制器并发超支。订阅回合独立预占且不退还。API 每请求最多 120 秒、Codex 整回合最多 115 秒、实验进程组最多 900 秒，之后 TERM/KILL；模型控制不能只靠 Humanize 的 cost=0 或配置声明。

独立测试也是执行候选代码，故复用 Humanize fence，以目标目录只读、单独 scratch 可写、无 API host、无认证状态读取权限运行。五个实际仓库均追加完成此隔离复验；历史首次执行记录不重写。Sol 的设计验收由独立 add/merge/异常/函数委派检查确认，模型声称通过不足以验收。

同冻结任务/基准 commit/环境/模型/effort 的原生 DSH 与 Humanize 各一次，保存墙钟、API 流时长、首 delta、CPU/RSS、Token 和 commit。原生 SDK 默认 composition 与 Humanize 禁用目标/网页、未压缩会话等设置仍有差异；API 生成长度、缓存和网络也不同。只报告实际时延与非 API 残差，不能由单次结果证明 Humanize 更快或准确估计纯调度开销，后续 P6 才做重复/随机顺序/配置完全对齐。
