# ADR-0024：按用户决定增加主集角色时间

2026-10-12，状态：用户明确决定，已实现并冻结；实际模型结果仍由新run回执验收。

## 原因与决定

用户看到较多超时，要求暂停核验，随后明确选择“公共15min，科研20min吧”。已完成v9两题5/12 PASS；Black-2八个编码角色都在115秒触发MAIN_ROLE_DEADLINE，B/C因为没有合格候选FAIL。Requests-1963五臂独立PASS、E接力超时。旧短时限不足以排除任务时间不足的解释，不把它当作一般能力/融合效力结论。

新v10对每个公共任务角色给900秒，对每个科研角色给1200秒；涵盖原生DS、N3各候选、Reviewer、Sol Builder和独立评分。LAV阶段使用同一家族角色截止时间。整题控制器模型活动保护分别7200秒/10800秒，给串行及并发角色留足外层空间；A–F的相同角色额度一致，额外角色实际耗时/Token仍计入。单请求120秒由DS/LAV broker强制；原生Codex CLI内部provider请求时钟不可见，实际核验的是整个角色900/1200秒硬限，不宣称其每次内部HTTP请求已独立验收。

累计API10000次且USD100、DS每角色100请求、Codex每角色一个逻辑预留、输出4096、既有上下文/资源/fence/独立隐藏验收/LOCAL_ONLY/数值容差/冻结任务和模型身份不变。碰到请求/输出/费用保护仍停止，不假装一定能够完整使用角色墙钟额度。独立科学数值验收仍为PC7200/TMS600/EGL1800/GC180秒，不能混作编码时间。

新授权 `configs/budget-p6-main-v3-time-approved.json` 单独保存，不改写旧config。锁内明确从v2进行时间修订，先存旧账本精确字节，再更换授权指纹；保留全部897请求、39订阅预留、USD15.1468026保守上界及未知usage。修订不能改变其他授权控制，旧授权入口不能继续写新账本。

## 执行证据与边界

实际发现并修正MeteredDriver默认600秒截断对新版的影响，老阶段仍默认600秒；科研提示词改为由实际任务时限生成。外层进程/角色watchdog、Humanize Flow/native driver和LAV采用一致任务分配；冻结清单/结果验证绑定每个任务的时限，不能给某臂额外加时。

时间控制v3：公共与科研两类，原生DS、Flow DS、原生Sol、Reviewer、Judge十项真实零模型描述符/Harness字段/OS隔离检查PASS，剩余整题时间变少时角色额度确实缩小；账本SHA前后相同。v1遗漏控制payload的manifest，v2遗漏非秘密canary文件，被严格检查拒绝；均为零模型控制，日志与工作区保留。修复的是控制fixture，没有放松隔离。新文件策略四项真实Git/公开/私有正负控制再次通过，账本不变。原16题的私有科学/公开正负控制和数值阈值继续保留。

v9原两题execute/sensitivity完整结果、第三题人为暂停部分样本和原始索引均保留，暂停不是模型FAIL。v10从新任务/工作区/独立会话运行，旧样本不混进新版完成率，不能挑最佳尝试或重标签。用户的新设定解除先前因时间讨论的暂停；只有新的有限批次获得当前授权，原暂停批次不原地恢复。基础设施失败仍停止，没有自动retry/额度结转/发布。

首补丁/首测试通过/用户接受墙钟及原生provider排队/生成细分事件仍缺可靠测量，报告继续unavailable，完整P6不能由新时限/CI/打包通过推断。科学数值通过也仍须独立源码、报告、图形审阅。P7重新安装包准备沿用授权，实际精确源码验收后再记PASS；产品每次PR仍人审，对外发布仍须确认。
