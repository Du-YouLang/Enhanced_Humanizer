# ADR-0059: Complete native CLI assets and actual execution controls

Date: 2026-11-26. Status: infrastructure defect proven; repaired package and local command controls passed; final exact-source gates required before further provider calls.

The initial fresh benchmark safely stopped at the handoff boundary. The CLI main executable had been copied from the official platform package without its adjacent codex-code-mode-host. Real rollouts explicitly reported a missing host, and the coding worktrees remained at the baseline. API completion/model identification, --version, model enumeration, fake-agent replies and shell permissions did not prove native tool execution. The omission was in our installation; it is not evidence of solver inability or provider overload.

Preserve the original frozen executor, complete role/session outputs, tool errors, programs, journals, timings, usage and cumulative reservations. No complete model-task group or hidden comparison closed in the affected attempt. Its prefix is an invalid infrastructure trial, not a genuine model-failure sample. A separate repaired trial must identify the affected attempt, retain its evidence hashes, and run only the originally requested task matrix under the existing cumulative authorization. It must not overwrite earlier results, refund unknowns, reset accounting or merge invalid timings into normal flow comparisons.

Install the full official npm platform archive into a new immutable versioned directory. Keep vendor/bin, codex-code-mode-host, codex-resources, codex-path and license/metadata layout intact. Bind every package file's SHA-256 separately from repository source pins; give the existing OS fence read access to this runtime bundle, never write access. Do not mix helpers from another version or edit old frozen installations.

New mandatory zero-provider controls use the actual official Humanize/Codex adapter, PID namespace, Code Mode runtime and existing filesystem fence. Only model responses come from a loopback scripted SSE fixture, using a role-private supported model-provider config with no credentials. Each case runs in a fresh process, matching production and avoiding the SDK's cached temporary fence launcher. A real command must read/hash the entire input, demonstrate allowed workspace writes for builders and denied writes for reviewers, and fail to write controller authority. The deliberately incomplete original package is a negative case and must be detected. Verify no real provider access and byte-identical real ledger before/after. This replaces the inadequate assumption that CLI version and fake-driver success establish tool readiness.

The current CLI emits custom_tool_call with call_id/input and custom_tool_call_output with call_id/output (possibly content arrays). The handoff verifier must support this observed envelope as well as legacy normalized events. Bind call/result IDs, exact path, byte count and hash; an echoed prompt hash without a successful result is insufficient. Match the trusted missing-host error explicitly and stop after the first such workflow failure. Publish observer state after post-execution classification, distinguishing model turn completion from usable workflow evidence.

The cumulative authorization is already active. Under the sole experiment-owner lock, validate and archive current ledger bytes, including the infrastructure trial; do not amend the same authorization again. Independent scientific source/report/figure review, complete-input handoff, private acceptance barrier, I/O sensitivity protocol and product human-PR/release gates remain.
