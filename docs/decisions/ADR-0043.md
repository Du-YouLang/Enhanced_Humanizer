# ADR-0043：DeepSeek 连续网络尝试10次，独立冻结后续协议

日期：2026-10-15。状态：实现与零供应商验证；正式调用另取启动回执。

用户说明本机正在同时下载四份约1GB文件和上传200MB以上文件，并要求DeepSeek调用多尝试几次。这是可能的连接拥塞因素，不是已经证实的故障根因。

旧批次`formal-full-compare-20261015T012431Z`在Black-5/P1/DeepSeek停止：903.425秒、控制器ROLE_TIMEOUT、103次wire尝试，38条临时连接错误、26条RECOVERED，最后broker事件为ROLE_DEADLINE/consecutive=0；SDK最后将代理返回的502视为SHOULD_RETRY。冻结Pi包装器因此记为INFRA_RETRY_PENDING。原标签、轨迹、候选、39条未知用量预留与receipt 7aedeaf9保留；不能把最终SDK标签当作未恢复网络或供应商过载证据，不能整格重跑已耗尽900秒的角色。

新策略只影响未来未开始的DeepSeek阶段：同一模型请求最多10次连续wire尝试（含首次），等待2、4、8、16、30、45、60、60、60秒；第五次起记录network_warning，第十次停止并要求网络核验。每次尝试先计账，部分流缓冲到完整后才交给工具，未知预留不退款。单次600秒、角色900/1200秒、角色1000次及累计10000次/USD200仍约束所有尝试与等待。角色时间或预算不足可提前停止，不能保证十次全部执行。

DeepSeek只由计账broker重试，关闭该新路径的SDK叠加重试，避免代理的角色超时502被再次当作供应商连接失败。ChatGPT订阅路径与旧策略保持原冻结配置。账本授权不改写：新配置是单独校验、写入新plan及新worker回执的transport策略，不能作为新的MainLedger授权。旧内容寻址执行器及计划保持。

新全主集入口只允许准备/控制此策略，拒绝直接启动112格重放；正式续行须通过有序旧回执链，只选86个未开始格，另冻新执行器契约。新旧计划除transport与执行器pin外，任务、模型、时间、数值标准、预算和保留证据必须相同；实际零模型控制与精确CI成功后才能启动。结果分别标注协议版本，不宣称与旧样本同协议。

当前旧账本6850DS/210订阅/USD171.8074293保守上界，剩3150次/USD28.1925707；实付不可见。缺少供应商usage的39次尝试不能填0或由重试成功反推退款。现有观察器仍只读，Luna核对状态，Sol负责代码与科学判定；产品逐PR人审和外部发布确认继续保留。
