# ADR-0018：同机标定后运行独立 P6 主集协议

2026-10-12，用户要求完成 PC-ALM 标定后继续 P6 与 P7；沿用 ADR-0016 的本机计算、独立主集账本及无累计 API 上限授权。外部发布与每个产品 PR 的真实人工批准要求不变。旧 smoke、v1/v2 清单、旧结果及旧 P7 安装包不覆盖。

PC-ALM 控制器补齐旧参考的最后一格，另建来源清单组成完整75格参考，保留旧74格目录。12配置执行同进程三遍及两组独立进程，共60次重复训练；准确率最大差异0.13pp，余弦最大差异0.016473591327667236，同进程36次逐位一致。在任何正式候选生成前冻结准确率0.25pp、余弦0.02。旧参考、官方源码和数据指纹前后相同；原中断原因仍未知，不能归因于GPU或模型。

标定是零模型控制，不等于完整提交通过或科学声称成立。PC 提交还必须执行 smoke、公开锚点、完整75格、原生三文件/manifest/报告核查与由完整程序哈希选出的两格独立重放。可信完整提交正对照与缺失实现负对照通过后才能向该任务发题。C1–C5单独报告，科学门失败不自动否定忠实执行，也不能调参消除。

新主集使用独立 v3 清单及 `P6_MAIN_LOCAL_20261011` 账本。保持原12公共身份、4科学方向、seed42、N3、A–F、原版J1和独立Sol/J3；Jev明确报告用户地区限制。所有编码/Reviewer/Verifier角色的实际外层和Harness整turn限时统一115秒、每角色20 API请求或1订阅回合，活动实验1200秒；资源上限为进程树8GiB/64进程/512线程。沿用Humanize与官方DSH/Codex，不开发替代编码工具。

科学任务公开检查与私有完整执行分开：PC保留官方15项测试，GC执行公开数值测试，EGL检查带符号乘法更新，TMS公开检查只验证语法并明确其不足。所有选中程序先冻结，之后才开始私有独立验收，分别记录模型/公开测试活动时间、独立执行时间和实际总墙钟。相同完整程序可共享同一验收回执，不能重复统计成不同独立实验。科学数值通过仍需来源/报告/图表审阅，不能自动转为PASS。

Requests的新主集把原测试的HTTP和HTTPS远端依赖统一路由到项目本机双协议fixture，保留原测试断言、TLS主机名及项目专用CA；不依赖公网httpbin的间歇性TLS可用性，也不修改全局信任。两项Requests重新执行buggy FAIL/gold PASS，形成私有controls-v2链；旧控制及失败日志保留。这属于新协议，不把失败准备计为模型错误。

每次运行冻结部署源码、入口指纹、开发提交、清单、公开提示和权限；计费入口要求干净提交。所有私有参考、任务卡、原始轨迹、控制结果和密钥留项目私有路径。完整工具轨迹敏感性是单独记账的新评审实验：候选程序/patch/head不变，证据池哈希有意改变；完整tool call/result不能截断后声称完整，provider headers和私有推理不导出。

采用带总超时的独立本机控制进程，保存PID及启动时钟和私有日志；活动期间拒绝重新部署源码。该进程只执行本次有限实验，不自动重试、不安排定时续跑。基础设施失败保留现场和已用额度，必须明确调查再决定新的尝试；未知Token、账单或订阅金额不能记为零。

P7随后基于实际验收源码重新打包、独立安装和回滚验证，保留旧包。开发GitHub交付可按实际CI成功推进；安装准备不等于对外发布。

合同7.2的Judge共同池同时保留原N3和含Reviewer M的扩展池，J0/J1/J2/J3均绑定各自同一冻结池。两组LAV采用独立scope/cache/回执，不能把原N3的J1与扩展池J3直接当同池对照。完整工具轨迹敏感性也覆盖这两个池，原生Codex Reviewer的tool call/output归一化而不导出私有reasoning；候选生成重放0，额外评分逐笔记账。

为计算Judge选中准确率，私有验收覆盖原N3/M及A/D/E/F最多8个完整程序，在所有公开选择冻结且模型密钥清除后执行。未通过完成/clean commit/保护文件/公开测试硬门禁的候选记FAIL并明确私有执行未运行；其余候选独立执行，数值通过但审阅待办保留INDETERMINATE。控制器总超时扩展为1200+8×任务独立验收上限+120秒，单次验收上限不变；实际观测裁判开销和各臂选中程序验收耗时分开，不把未选中候选的测量藏在预处理内。J3缺失时增强C/F保留诊断结果但不能记PASS或默默退回J0。
