# ADR-0019：保留首轮主集失败并区分本地请求上限

2026-10-12，v3 主集第一次真实执行在 BIP-black-2 的 native DS 回合停止。20 次 API 请求均有完整 usage，输入（含缓存）422935、输出9302、缓存读取400128，API 保守上界 USD0.1380429；实付账单不可见。私有计量代理明确记录 `Role request cap exhausted`，它的本地 HTTP402 被 Harness 包装为失败，外层错分为 INFRA_FAIL。没有证据表明上游账户余额不足。该 batch、源码快照、全部请求及96项未完成表保留，不覆盖、不退款、不筛选成功重试。

v4 保持相同16题、A–F、seed42、N3、115秒、20请求/1订阅回合、环境、材料、隐藏判据和所有计算限制。仅有可信本地 broker 的纯请求上限拒绝可以把 INFRA_FAIL 派生分类为 BUDGET_EXHAUSTED，保留原始 worker 状态和错误；该角色选中臂记 FAIL/ROLE_REQUEST_CAP，失败候选不能被评审变为合格。上游402、未知拒绝、策略拒绝、混合拒绝及超时不适用。基础设施故障仍停止 batch，模型额度不足不自动重试，也不放宽上限。

新 v4 清单单独冻结并固定新的完整源码哈希。v3 与 v4 的实验不能合并为单一成功尝试，报告须同时列出 v3 首次失败和累计主集账本用量。重新执行是本次已授权工作中针对已查明分类错误的明确新版本实验，不是自动重试服务。历史 smoke/阶段账本和私有验收结果不变。
