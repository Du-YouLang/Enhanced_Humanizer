# ADR-0011：P5 本地交互工作台与原生执行控制

用户授权 P4→P5 本地开发、按需实验预算，随后明确暂缓 GitHub 推送和 PR。P4 已本地独立验收。因此 P5 使用单独本地 phase branch，远程交付保持 PENDING，P6 未开始。

评估了已固定 Humanize Web：stdlib HTTP、ES modules、daemon/frontend，但现有前端未提供工程事件 DAG 与跨运行的证据/恢复图。按指导书允许的独立轻量页面方案，增加同类 stdlib loopback HTTP + 无构建 ES module 页面，直接读取 P4 事件库，原生 Humanize workbench_loop Flow 负责 checkpoint/执行。DS 候选复用 ds_candidates、DSH、protected broker；Sol 角色复用既有独立 Codex Harness/fence，不另建 Coding Harness。可视规范参考 [diagram-design](https://github.com/cathrynlavery/diagram-design) 的简洁 HTML/SVG 布局；图数据来自真实结构化事件，SVG 只绘制动态连接线。

模型固定 deepseek-flash/gpt-6.1-sol；J0=硬测试规则、J1=原版 LAV 概率算法、J2=Jev地区阻塞、J3=独立 Sol 结构化评分，不能互换标签。N=1/3/4/5 是真实生成数；添加 M 的评分池允许2/6个元素，通过显式 JUDGE_COMPARISON 区分，不扩展真实生成范围。

用户按需预算授权下，选取有限 P5 操作上限 USD5 /160 DS请求 /16 Codex预留回合；界面可下调，账本跨任务累计，不因重启/恢复重置。单请求≤120秒、候选/角色≤600秒、运行累计活动≤1200秒；单候选另限12请求/$0.5。不会充值；用尽停止保存。API现金、cache/input/output与订阅回合分开；缺 usage 不回收未知预留，账单 unavailable。P0–P3 账本不改变。

后端只监听 Windows 127.0.0.1。owner 直接导航建立随机 HttpOnly SameSiteStrict session，所有写请求还验证精确 Host/Origin/CSRF和1MB大小；拒绝 actor/capability 自称身份、未知字段、越界路径。模型工作进程位于不能访问 Windows loopback/磁盘的受限 WSL fence；此方案信任 Windows 本机账户及其特权进程，不能声称能阻挡本机管理员伪造浏览器头，也不是多用户互联网部署的身份系统。若需要网络/多人部署必须另立安全设计。

每个真实产品 PR 的审批绑定精确head、证据、目标、时效并单次消费。当前准备审核只产生本地提案，所有远程发布请求后端硬拒绝，遵守用户暂缓。开发历史 PR链接不构成产品批准。测试fixture批准明确标注，不代用户批准模型产物。恢复连接后仍需目标repo/基线祖先/隐私/CI/审批预检，不能将合成任务代码推到工作台仓库main。

暂停是可见的角色边界请求，当前有上限的调用可完成；停止触发嵌套 Flow取消、namespace进程组收束和partial保存。只从 durable PAUSED checkpoint恢复，已完成调用不重放；进程重启标INTERRUPTED，不自动续费。失败代码与基础设施失败分开；外部订阅配额失败保留 INFRA_FAIL/usage unavailable 和预留，不能当作代码失败或用mock验收。

完整 P5 Gate 以真实浏览器操作、后端对抗检查、真实执行/暂停恢复/停止/历史继续和冻结独立复验为准，不以页面加载替代验收。此文是设计决定，具体通过与阻塞见阶段报告。

00:50 后的实际探针保留了官方 Harness 的一次失败重试和随后已完成的 Sol 会话。旧的 `len(usage)==1` 验证误拒绝此结果，修正为：必须恰有一个 COMPLETED turn，按其 session ID 唯一匹配原生 trace，并核验实际模型及完整非负 Token 证据。全部失败/重试 trace 和未知 usage 仍保存，不退款未知预留、不合并会话身份。源码变化后不得恢复旧冻结源码检查点；明确创建新 run 重用原候选池，旧 INFRA_FAIL 不改写为成功。

真实暂停恢复又捕获了 Reviewer 前的公开证据视图哈希错误。J3 的 pool_hash 对应 `judge_pool(handoff)` 的公开视图，而不是含私有硬测试的原始池。新增显式匹配该公开视图及 rubric 的转交函数，重新计算 handoff_hash；不接受其他池评分，也不向角色转交隐藏测试。原失败 run、已完成 J3 和边界暂停继续保留。

公开视图中的可见测试耗时也是证据的一部分，重跑可见测试会改变 digest。P5 在第一次评分前一次性持久保存 `candidate-handoff.json`，Reviewer 和 A..M 比较复用同一份冻结报告；恢复时校验其 hash 和原池身份，不重新测量后冒充同一评分输入。原生零模型控制使用真实冻结池 + 明确 J0 检查这个接口，再进行新的真实 Sol 链。

真实 Reviewer 曾报告 A/B/C/M，已完整覆盖输入但旧的全列表相等校验误拒绝。校验保持所有输入必须出现一次，允许单独附带输出 M；遗漏、重复、未知 ID 仍拒绝，原协议失败不改写。暂停时也转出新提交的 bundle，让尚待硬测试的 Reviewer checkpoint 能合法分叉；COMPLETED 不等于硬验收 PASS，PR 提案仍需后续硬测试通过。
