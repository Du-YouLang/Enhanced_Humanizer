# ADR-0008 — P2 task-level candidates and frozen-pool judges

Status: accepted for implementation; efficacy unproven. Date: 2026-10-10.

The user authorized P2 and a separate USD 2 / 100 DeepSeek requests / 6 existing-subscription Codex judgment turns budget: 120 seconds per API request, 600 per candidate and 1,200 per experiment. No top-up. P0/P1 ledgers remain unchanged. Development PRs follow ADR-0004; product results require human review.

Humanize's custom Flow schedules N=1/3/4/5 complete candidate processes. Each runs the existing Humanize Builder Flow and official DSH SDK/runtime, with tools, editing, tests and commit. This is task-level sampling. [TurboAgent](https://github.com/llm-as-a-verifier/TurboAgent) supplies a request-level proxy and remains a separate optional comparison. No model/tool execution loop is reimplemented.

Candidates use independent `--no-local` clones/object stores with no remote, the same frozen base/task/environment, separate HOME/Humanize/DSH/cache/tmp and Session/broker capability. Private PID/mount/user namespaces hide sibling `/proc` state. `--map-current-user` keeps uid 1000; effective capabilities are zero after exec with no-new-privileges. Humanize's existing Landlock/seccomp/network fence confines each runtime. Candidate-code verification and Git evidence export also use private PID namespaces and fences. Before inference, negative tests execute under the actual runtime fence against sibling code, Git authority and sibling backend/cache state. Namespace setup is trusted local orchestration; agents never run as root. Namespace exit kills remaining descendants. Windows mounts/interop stay disabled.

The shared locked phase ledger reserves the full documented request bound before HTTP, with additional per-candidate 12-request / USD 0.5 limits. Unknown usage retains the full reservation. Concurrent candidates use separate brokers with one in-flight request each. Every forwarded DSH retry is charged and recorded; outer automatic reruns are disabled. Queue delay, first observed patch, first visible-suite pass, completion, HTTP time and verification time remain separate. Provider queue/tool-only time is unavailable when not measurable. Polling timestamps include the observation interval.

Hard tests execute candidate code read-only/offline without auth state. The controller supplies the suite outside writable candidate files. A clean new commit and unchanged visible suite are mandatory. Failed/timeout/infrastructure candidates and bundles are retained. All-failed pools produce FAIL or INDETERMINATE and reproducible diagnostics, never a successful best failure.

Every judge receives one compact canonical evidence object with the same pool/rubric/evidence hashes, including failures. J0 uses hard-test eligibility and stable ID ties. J3 uses a fresh Sol Verifier session, read-only code permission and structured scores. J1 calls unchanged fixed upstream LAV `select(client=...)`, injecting only a metered HTTP transport. Both score positions must contain genuine scale-token distributions before upstream extraction; its literal fallback cannot masquerade as probability scoring. K=1, one pivot and seed 0 are smoke settings. Two low-effort attempts exhausted the 4096-output budget before score tags appeared; both remain BLOCKED_LOGPROBS. The successful strict run explicitly disabled LAV thinking (upstream-supported off), keeping extraction/tournament code unchanged. Configuration changes use a new cache identity and retain prior caches and costs. LAV caches are keyed by pool and rubric, never candidate index alone.

J2 implements the [official Jev typed Score interface](https://docs.typesafe.ai/introduction/quickstart) behind an authorized transport. No Jev credential or vendor-specific budget exists: live J2 is BLOCKED_CREDENTIAL with zero requests. Other routes continue. No unlicensed example source is embedded. Judge identities remain distinct and none override failed hard tests.

The P1 Linux dependency lock is unchanged. Fixed MIT LAV source from the verified user Fork is imported directly with LICENSE preserved. Optional provider SDK constructors are unused; the public injected-client seam uses existing httpx. No new coding harness or redundant provider SDK is installed.

Limits: same-kernel namespaces/fences do not prove resistance to kernel bugs, every Unix socket or side channel. This fixture does not establish scientific correctness or Best-of-N/judge improvement. P3 synthesis, P4 research memory and P6 ablations remain separate. Raw model logs stay private; only reviewed synthetic evidence may be published.

Traceability: DS-01..09, JR-01/02/03/08, HR-01/02/07, CX-02, OP-01, SG-01; Issue #7. Original v0.4 files remain unchanged.

Sol Verifier uses a private runtime home with an in-place symlink to the independently authenticated Linux auth file, without copying the global auth directory or prior sessions. Broad old Codex-home access is removed. Actual fence probes deny prior Builder session reads and candidate evidence writes. Initial startup failure is preserved.

Custom frozen task contracts support exact base SHA, prepared project-local source repository, fixed environment hash, prompt, protected file hashes and external visible/hard test programs. This includes building a tiny project from an empty base. Custom research inputs/results stay private. The generic contract is additionally verified offline, without claiming another real model task.
