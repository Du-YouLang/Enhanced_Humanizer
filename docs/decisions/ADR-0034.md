# ADR-0034：Pi正式对照的认证与消息兼容边界

2026-10-14，在用户授权的16格正式Pi比较范围内，固定原有两任务/四profile/双provider，不启用256格方案。共用原累计USD200/10000次账本；订阅回合与API现金分开，SDKdispatch不冒充服务商内部wire计量。GitHub和外部发布继续暂缓。

继续复用官方Pi 1.1.0 SDK、资源和工具。订阅凭据经stdin进入官方AuthStorage内存，实际文件不在模型工具的可读范围；官方刷新结果经单独管道传回受保护控制器，保留单文件备份。独立实际隔离、Token计量正负、Research Loop后台/Git检查点/拥有者和原裁判正负控制是付费之前的门禁。科学任务在原沙箱允许的benchmark/private目录内执行，没有扩大目录或网络权限。

首个真实工具门禁的HTTP422请求保留未知usage预留；原完整错误body不可见，不能假报确切服务端原因。零模型证实Pi默认developer角色与原DSH请求的system角色不同；v3显式设置supportsDeveloperRole=false，并在转发前核对角色白名单。额外developer负控制必须在上游调用和工具执行之前拒绝。原v1/v2清单、失败回执和请求不覆盖，不通过调Token/时间/数值阈值绕过。

冻结后按真实工具门禁→16格串行比较→科学源代码复核顺序推进。每格先冻结提交，再看隐藏结果；原A–F和历史失败不重跑。基础设施错误不冒充模型科学失败。Research Loop控制不证明断电后训练自动续跑，阶段完成/失败现场必须保留，不重复已完成模型阶段。
