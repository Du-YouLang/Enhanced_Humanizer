# ADR-0025：按用户明确决定恢复 DSH 每请求 256000 输出额度

2026-10-12，状态：用户明确授权；新版协议独立冻结，实际主集结果另验收。

用户要求重新处理 DSH maxToken，随后明确要求使用默认256000，不采用代理提出的16384折中。该决定仅改变后续请求输出策略，不重置累计10000请求/USD100、公共900秒/科研1200秒、单请求120秒、LOCAL_ONLY、数值门、独立评分或产品PR人审要求。输出额度是每个模型请求的上限，不是整个角色的累计输出，也不代表每次必须生成256000 Token。

根因在项目：`p1_budget.MAX_OUTPUT=4096`和Broker硬限由早期小实验延续到主集。官方installed SDK/runtime0.1.5rc1及Humanize0.1.0b2仍复用；真实API由计量代理直连`https://api.deepseek.com/chat/completions`，没有第三方网关。官方当前[DSH适配器文档](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/llm/llm-deepseek/README.md)记默认256000；[API文档](https://api-docs.deepseek.com/quick_start/pricing/)列Flash最大输出384K、上下文1M。当前upstream文档的Messages传输与本项目固定wheel的Chat Completions不同，不能用文档替代真实安装版本验证或静默升级。

新版仅在每个独立角色的DSH_HOME写`llm-deepseek.maxTokens=256000`；Broker独立执行相同上限。LAV沿用模型身份和评分算法，读取新输出额度，缓存/配置身份包含实际额度。所有编码角色（包括Sol、Reviewer、接力）的公开提示采用相同分步写入/小补丁/检查落盘/简短收尾指令。没有添加替代Harness、失败后自动“继续”或自动重试。结构化max-tokens仍记录OUTPUT_LIMIT，不能重标签旧失败。

MainLedger新请求逐行记录输出上限与策略版本，调用前最坏预留为`1048576*300+256000*1200=621772800` nanoUSD（USD0.6217728）。仍按峰值全输入保守计费，不把未生成额度算成实际费用。旧4096行及未知预留继续使用旧逐请求边界；锁内修订先独立保存旧账本精确字节，再更换授权指纹，必须逐字保留全部请求/订阅/费用；旧授权入口不能重新写入。SDK显式更小请求可保留更小输出，但费用预留仍保守。

不凭回答长度推断API限制、不猜测私有科学数据；近期四个DS角色有真实max-tokens证据。当前截断不是已证实的compact失败，故不扩大压缩模块额度或更改压缩算法。API在输入和输出预留超过窗口时可能拒绝请求；256000不是绕过服务端容量的许可。单请求120秒仍有效，最终失败分类必须保留实际请求/角色期限证据。

v11冻结16题/A–F96单元，原v10及之前源码/轨迹/账本/结果保持独立。v10核验时控制器已不存在、没有整题完成回执，且无遗留工作区进程；退出原因unavailable，保留不完整样本，不能假装整题完成或记模型FAIL。原始索引先备份再明确停止输出策略讨论；新版不原地恢复旧尝试。

真实零模型installed DSH+角色私有profile+Broker HTTP+逐请求结算控制：旧4096返回max-tokens，新256000完整接收synthetic5001输出，显式更大SDK请求仍受256000限制；provider请求0、真实phase账本逐字不变。首次控制脚本错误期待SDK返回error，实际为max-tokens，原失败fixture/回执保留，修正的是期望值。原生时间十项与文件策略四项新控制通过。具体源码、测试、CI和实际模型结果见[P6输出审计](../audits/P6-DSH-default-output-2026-10-12.md)。完整P6接受和新版P7包仍以各自回执为准；外部发布仍须人类确认。
