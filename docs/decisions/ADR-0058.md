# ADR-0058: Separately audited I/O-adjusted elapsed-time estimate

Date: 2026-11-26. Status: requested by the human before any refresh inference; prospective implementation and exact-source controls required.

The human requested a separate elapsed-time view excluding hard-drive I/O. Keep raw method wall time as the primary result. Never subtract Windows disk-busy percentages, global WSL pressure, or sums of per-process I/O delays from a parallel flow's wall time.

Use accounting-only cgroup-v2 groups for each method and a separate hidden-acceptance epoch. The trusted setup process only creates the new run's group and places a newly forked child into it; it drops all groups/UID/GID to workbench before executing any controller or Harness. Candidate workers remain non-root and retain the unchanged OS fences. No CPU, memory, I/O weight, throttling, global delayacct/sysctl, or network configuration is changed. No existing process from another project is moved.

For each epoch record both monotonic/wall-clock pairs and the kernel's per-group io.pressure some/full cumulative microsecond counters at both boundaries. Subtract only the delta of full: it measures simultaneous local full I/O stalls and avoids adding overlapping waits from parallel builders. Retain some for context, never subtract it. Validate nonnegative counters and full≤some≤observation constraints as applicable; missing or incompatible counters are unavailable, never zero. Retain raw observations and errors.

Report raw_elapsed_seconds, full_local_io_stall_seconds, and io_adjusted_elapsed_estimate_seconds = raw_elapsed_seconds − full_local_io_stall_seconds. Keep method model/public time and hidden scientific acceptance separate. This is an observed local-stall sensitivity analysis, not measured causal performance on a hypothetical zero-latency disk: remote generation/network may overlap local stalls, asynchronous I/O is not fully removed, and required flow I/O cannot be separated from external device contention by these counters. The counters cover local I/O, not uniquely G-drive latency. Do not replace primary rankings or declare significance from adjusted estimates alone.

Actual preflight: kernel task_delayacct was disabled, so old per-process zero counters cannot prove no I/O. A separate UID1000 accounting-group probe measured 0.5002s CPU with zero full stalls and 0.0798s fsync workload with 0.016855s full stalls. Probe dispatched zero models/candidates and changed no global kernel setting. This demonstrates capability, not final-run measurement. Final source must run its own CPU/fsync controls and all existing fencing/public helper controls before models.

Historical benchmarks lack these counters. They remain unadjusted/unavailable; never manufacture an SSD-equivalent time. All old programs, results, unknown usage, authorization amounts, role limits and private thresholds remain immutable. See Linux primary documentation: https://docs.kernel.org/accounting/psi.html and https://docs.kernel.org/accounting/delay-accounting.html.
