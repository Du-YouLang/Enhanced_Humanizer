# ADR-0032 只读监控恢复与 GRANGER 轨迹分析

日期：2026-10-14。用户要求跟进已授权工作，并亲自以管理员身份安装项目只读监控的计划任务。GitHub 继续暂缓。

本机在 09:27 重启后，原监控进程不在，最近心跳为 08:35。原 HKCU 登录启动项仍存在，未执行的具体原因尚未证实。恢复使用 Windows 计划任务的登录触发和每分钟触发，任务以当前用户的最低权限、交互式登录令牌和隐藏窗口运行，不存储密码，不要求重启。原启动项保留，旧监控通过自身 enabled 标志停用，配置和旧状态均另存。

计划任务只调用经过源码与配置哈希检查的现有只读观察器。原观察器的文件锁和任务的 IgnoreNew 设置避免重复实例；用户禁用观察器后，恢复程序也遵守该禁用状态。观察器不派发模型、不修订预算、不恢复候选任务。管理员权限仅用于用户亲自注册任务，运行权限保持 Limited。首次非管理员注册被 Windows 拒绝，失败文件保留；用户执行修订安装脚本后，任务动作、触发器、窗口设置、无限运行期限及返回码已独立核对。

旧巡检把固定配置中的原 WSL boot ID 用于所有新运行，导致重启后启动的控制器被显示为 EXIT_WITHOUT_RECEIPT，尽管进程仍在运行。补充观察器 v4 保留原检查器和原批次，额外绑定本次运行的真实 boot ID、PID、启动 ticks、命令哈希、启动回执和运行合同。跨启动的 PID 不会被认领为活动进程。观察器迁移没有改写原生实验的 59 份源码或实验协议。

GRANGER 同池完整轨迹分析此前没有启动记录。本次在零模型检查中确认原候选、完整轨迹、冻结协议、源码和预算一致后，由正常实验入口启动这个未开始的阶段。使用原现金预算后继 checkout，没有重试候选、重放数值验收或改变原六臂选择。该阶段完成后，再次独立验证完整回执、四项付费评分完成状态、所有源码及累计账本的历史前缀。

主流程完成数仍为 15 题，包含 FAIL；轨迹敏感性由 14 次增至 15 次。Black-5 的 Pool-A 是原有网络中断，原 DS0、Pool-B、Pool-C 已完成，尚未冻结最终选择。本次仅核验其现场，没有重跑或补生成该候选。完整 P6、Pi、新 P7 及外部发布继续分别待验收。

详细结果及恢复控制见 [本机监控与 GRANGER 跟进审计](../audits/P6-followup-2026-10-14.md)。
