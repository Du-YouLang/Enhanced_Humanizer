# ADR-0005：批准项目专用 WSL2 与条件式 P1 启动

日期：2026-10-10。状态：用户明确授权；系统组件安装完成，等待用户手动重启，发行版与真实隔离尚未验收。

用户接受此前说明的空间占用，并指示安装 WSL 后如无其他问题直接开始 P1。这覆盖虚拟机平台变更、微软 WSL 系统组件使用 C 盘的例外，以及 D 盘项目下的 Ubuntu VHD、缓存与日志。D 盘预留 20 GiB，C 盘预留 4 GiB，预计新增环境 5–10 GiB；预算不是立即预分配或实际使用量。未经另行指示不自动重启、卸载、unregister 或删除 VHD。

使用微软稳定版 WSL 3.0.1 x64 MSI 和官方 Ubuntu 24.04.5 amd64 `.wsl` 镜像；版本、来源和 SHA-256 固定在 `configs/wsl-assets.lock.json`。安装前验证微软 Authenticode 签名。只启用 WSL2 必要的 VirtualMachinePlatform；不为 WSL1 启用旧子系统。发行版名 `EnhancedHumanizer-P0`，通过官方 `--from-file / --location / --name / --no-launch` 安装到 `.local-workbench/wsl/EnhancedHumanizer-P0`，不默认落到用户 Store 目录。已存在但位置不符时停止，不移动或覆盖。

发行版安装脚本在系统报告要求重启且 Windows boot 时间未更新时返回 `BLOCKED_RESTART`，不尝试启动虚拟机。当前 MSI exit 0，虚拟机平台 Disabled → Enabled，RestartNeeded true；WSL CLI 版本可读，不能据此宣布 Linux 可用。Ubuntu 下载完成也不等于安装完成。

WSL2 解决受支持的 Linux 执行环境问题，不能独自证明候选隔离。P0 仍须真实拒绝路径越界、相邻候选、宿主凭据和危险 Git 操作，再执行真实 Humanize Coding demo。主 Flow 继续复用 Humanize，Coding Agent 继续用官方 DSH/Codex；不使用 unrestricted agent 绕过 Windows 的 Unfenced 负结果。

P1 启动已获条件授权，P0 Gate 通过后无需再次请求阶段开始。用户另行批准 P1 USD 1 / 40 DeepSeek 请求 / 6 Codex 订阅实验回合 / 请求 120 秒 / 实验 15 分钟，不充值。单独保留 P1 ledger，不能清空 P0 记录；配置只是授权记录，执行前仍须真实预算控制。用户同时确认 P1 保留 Enhanced_Humanizer 名称。

回退：保留原 main、阶段分支与 Git bundle；代码可 revert。系统环境回退先停止项目发行版并备份 VHD，删除或卸载需要明确目标授权。安装失败或隔离不成立属于基础设施失败，不修改需求或将其报告为算法无效。

依据：[微软 WSL 安装](https://learn.microsoft.com/en-us/windows/wsl/install)、[基本命令](https://learn.microsoft.com/en-us/windows/wsl/basic-commands)、[官方发行版清单](https://raw.githubusercontent.com/microsoft/WSL/master/distributions/DistributionInfo.json)。
